### 2. Package exposure and optional ObsPy imports: remaining promotion work

**Demonstrated readiness gap, not a matching defect.** The implementation
imports ObsPy at module load in
[`associate.py:10`](../sandbox/obspy_association/associate.py#L10).
[`pyproject.toml:28`](../pyproject.toml#L28) deliberately makes ObsPy optional.
A direct eager re-export of that module would consequently make the reader
unimportable in a normal installation without the optional extra.

**Smallest proposed design, for discussion before coding:** move the
implementation into one private package module, keep the scientific rules,
and expose a thin `geocsv.associate` wrapper that imports the implementation
only when called. Missing ObsPy should produce an actionable `ImportError`
pointing to `mermaid-geocsv[obspy]`; do not hide unrelated import failures.
Keep `read` usable without ObsPy. No adapter hierarchy or custom exception
framework is needed.

Suggested public signature:

```python
associate(waveforms, records, *, time_tolerance=0.0001, allow_merge=False)
```

Retain in-place batch attachment and `None` return. Keep `TypeError` for an
unsupported waveform argument and `ValueError` for invalid, unmatched, or
ambiguous scientific inputs. **Omit `project_sac` until projection exists**;
the current sandbox option only raises `NotImplementedError`. This is a
proposed change to an experimental interface, not an implemented change or a
reason to build deprecation machinery.

Before exposure, move tests to the public import and check a built wheel
outside the checkout, including reader import/use without ObsPy and a helpful
failure on association without it. Current pytest path configuration at
[`pyproject.toml:43`](../pyproject.toml#L43) makes sandbox tests run; it does
not verify a shipped association API. CI's Python 3.12 job installs ObsPy;
its Python 3.14 reader job intentionally does not. Dependency absence in that
job is distinct from the removed fixture-related skips. CI was inspected,
not run remotely for these unpushed edits.

### 3. Timing, sample rates, and merged coverage: keep the scientific limits visible

**Established behavior.** The default remains an inclusive 100 microseconds,
using full UTC integer nanoseconds. Source lexical precision is preserved but
never used to enlarge that tolerance. A real P0030 example has a **349 us**
start offset: the default rejects it and explicit `time_tolerance=0.001`
accepts it ([test](../tests/test_associate.py#L47)). This is deliberate; it
does not establish either clock's physical accuracy. Do not quietly restore
the former per-row-resolution default.

The **0.01 Hz** check remains provisional scientific policy. Tests establish
both inclusive floating-point endpoints and immediately outside values
([test](../tests/test_associate_synthetic.py#L355)); they establish correct
application of the threshold, not its physical justification. Preserve both
original rates. Revisit its scientific basis separately if corrected upstream
rates or a broader waveform population require it.

For `allow_merge=True`, integer sample ranges must cover the waveform grid
exactly with overlaps counted once; source start and last-sample alignment
must satisfy the chosen timing tolerance. Counts have no tolerance. The
[merged-trace contract](../docs/OBSPY_MERGED_TRACES.md#fallback-requirements)
and tracked synthetic tests cover gaps, one-sample excess/shortage, overlaps,
ambiguous grid placement, and batch failures.

**Remaining scientific scope, not a new defect.** Range coverage cannot prove
which samples survived an archive overlap or reconstruct original Q/D
lineage. All raw attached values remain the anchor row's metadata; only its
position is adopted for the whole trace. Do not interpret anchor pressure,
rate, count, or quality as independently verified whole-trace metadata.
The saved July example's 25 ms override remains a separately documented local
check, not a portable fixture or justification for a larger default. Archive
reconstruction and future SAC depth projection need their own decisions.

### 4. Reader and identity policy: retain the now explicit contract

The [reader specification](../docs/READER_SPEC.md) remains the implementation
reference. [`read.py:562`](../src/mermaid/geocsv/read.py#L562) distinguishes
known empty string-valued `Location` from unknown (`nan` or a nonempty declared
missing marker). No other field receives this empty-string exception. Network,
Station, and Channel must be nonempty; only Location can be empty in a valid
association. Omitted identity columns and unknown identity values fail source
preflight. DataQuality remains independent evidence, not a matching filter.

Global exact SNCL/UTC-time/count/rate duplicates fail preflight, even if the
input waveform would not select them. Different counts can disambiguate the
same SNCL/time; distinct rows satisfying the actual trace tolerances still
raise. Missing or naive event times remain ineligible, with failure diagnostics,
rather than evidence that an unknown time could never have matched. These
policies are explicit and covered by tracked tests; do not reopen them as
unspecified compatibility questions during the package move.

The general GeoCSV interoperability questions in
[`OPEN_QUESTIONS.md`](../docs/OPEN_QUESTIONS.md) remain unresolved format
questions, including missing-token grammar and custom declaration scope.
They do not require a parser rewrite before exposing this MERMAID adapter.
